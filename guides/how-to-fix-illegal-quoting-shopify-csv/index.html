If you are importing products into Shopify and received an error message like:

Line 42: Illegal quoting on line 42. CSV header does not match data row.

You are not alone. This is one of the most common CSV rejections encountered by e-commerce managers, dropshippers, and inventory coordinators. Here is why it happens and how to resolve it.

Why Does "Illegal Quoting" Happen?

In a standard CSV (Comma-Separated Values) file, columns are separated by commas. However, product descriptions (HTML) and titles frequently contain commas or quotation marks (such as dimension indicators like 12" Screen or 100% Cotton, Made in USA).

According to RFC 4180 CSV specifications, whenever a cell contains a comma or quote mark, the entire cell value must be wrapped in double quotes. Furthermore, any quotation marks inside the text must be escaped by doubling them (e.g., ""12 inch"").

The error triggers when:

  • A quote was opened at the beginning of a description, but was never properly closed at the end.
  • An unescaped quotation mark (") appears in the middle of a sentence, making the parser believe a new column has started prematurely.
  • Excel exported "curly/smart quotes" (“ and ”) that corrupted the UTF-8 encoding.

Method 2: Manual Repair via Text Editor (VS Code / Sublime Text)

If you only have one row failing and want to fix it by hand:

  1. Do NOT open the file in Excel: Excel will often re-save and re-break quotes automatically.
  2. Open the CSV file in a code editor like VS Code or Notepad++.
  3. Press Ctrl + G (or Cmd + G) and jump directly to the line number reported in your error message.
  4. Inspect the description and title fields on that row. Look for inches marks (") or mismatched quotes.
  5. Replace stray individual quotes with "" or replace them with word equivalents like inches.
  6. Save the file ensuring the encoding format is explicitly set to UTF-8 without BOM.

Frequently Asked Questions

Why does Shopify say "CSV header does not match data row"?

When a quote mark fails to close, the CSV parser interprets subsequent commas as literal text instead of column breaks. As a result, the parser counts fewer columns in that row than exist in the header row, resulting in a column mismatch error.

Does Google Sheets fix this better than Excel?

Yes, Google Sheets handles RFC 4180 escaping better than Excel when exporting as CSV, but it can still struggle with complex embedded HTML description tags that contain unescaped quotes.
